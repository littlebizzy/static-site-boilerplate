# Security Headers

The root `_headers` file sets HTTP response headers for static assets deployed to Cloudflare Workers. `python3 build.py` copies it into `public/`. Rules under `/*` apply to matching static asset responses; headers on responses generated by Worker code need to be set separately.

| Header | Purpose |
| --- | --- |
| `X-Content-Type-Options: nosniff` | Prevents browsers from guessing a different content type. |
| `Referrer-Policy: strict-origin-when-cross-origin` | Limits referrer information sent to other sites. |
| `X-Frame-Options: SAMEORIGIN` | Restricts framing by other origins. |
| `Permissions-Policy` | Disables camera, microphone, and geolocation access by default. |
| `Strict-Transport-Security` | Tells browsers to use HTTPS on subsequent visits for one year. |
| `Content-Security-Policy` | Restricts where scripts, styles, images, and other resources may load from. |

## Before deploying

- Keep the defaults for a simple site with locally hosted assets and no inline scripts or styles.
- The default CSP allows the Cloudflare Web Analytics script from `https://static.cloudflareinsights.com`. Its `connect-src 'self'` also permits automatic injection to report to the site's own `/cdn-cgi/rum` endpoint. This allowance does not turn on analytics.
- Manually embedded Cloudflare Web Analytics beacons report to `https://cloudflareinsights.com` instead; add that origin to `connect-src` if using manual installation. See [Analytics](analytics.md).
- Adjust `Content-Security-Policy` if the site uses inline code, external fonts, other analytics, APIs, or embeds. Avoid allowing all sources just to silence errors. The current policy blocks inline scripts and styles.
- Review `Strict-Transport-Security` before deploying. Only retain it when HTTPS is reliably available; browsers remember the setting until it expires.
- Review framing restrictions if the site must be embedded elsewhere. `X-Frame-Options` and CSP `frame-ancestors` currently limit framing to the same origin.

## Verify

1. Deploy the site, then open it in a browser.
2. Open developer tools → **Network**, reload, and select the HTML document.
3. Inspect **Response Headers** to confirm the expected headers are present.
4. Check the **Console** for CSP violations, and verify that the site's scripts, styles, images, and forms still work.
5. Optionally check the public URL at [SecurityHeaders.com](https://securityheaders.com/).
